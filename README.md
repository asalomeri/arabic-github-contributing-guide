# دليل المساهمة في GitHub بالعربية

دليل عملي يساعدك على البدء بالمساهمة في المشاريع مفتوحة المصدر، من اختيار مشروع مناسب إلى فتح أول `pull request`.

## أول مساهمة لك خلال 30 دقيقة

ما تحتاج تكون خبيرًا أو تكتب ميزة كبيرة. تحسين صغير وواضح—مثل تصحيح خطأ في التوثيق—مساهمة مفيدة وتعرّفك على طريقة العمل.

### 1. اختر مشروعًا مناسبًا (5 دقائق)

ابحث عن مشروع تستخدمه أو يهمك، ثم اقرأ ملف `README.md` وتأكد أن المشروع ما زال نشطًا. ابحث في تبويبي **Issues** و**Pull requests** عن تعليمات المساهمة، وعن issues موسومة مثل `good first issue` أو `help wanted`.

### 2. افهم المطلوب قبل البدء (5 دقائق)

اقرأ وصف الـ`issue` والتعليقات، وتحقق أن أحدًا لم يبدأ العمل عليها. إذا كانت التعليمات غير واضحة أو التغيير كبيرًا، اسأل في النقاش قبل أن تبدأ. للمساهمة في هذا الدليل، يمكنك البدء بتصحيح معلومة أو تحسين شرح موجود.

### 3. جهّز نسخة من المشروع (5 دقائق)

- اضغط **Fork** لإنشاء نسخة من المشروع في حسابك.
- استنسخ نسختك إلى جهازك، ثم ادخل إلى مجلد المشروع:

```bash
git clone https://github.com/USERNAME/REPOSITORY.git
cd REPOSITORY
```

استبدل `USERNAME` و`REPOSITORY` باسم حسابك والمستودع. إذا كنت تعمل من المتصفح، تقدر تعديل ملفات التوثيق مباشرةً باستخدام محرر GitHub بدل استخدام الطرفية.

### 4. أنشئ فرعًا للتغيير (دقيقتان)

```bash
git switch -c docs/fix-typo
```

استخدم اسمًا قصيرًا يصف التغيير، واعمل على فرع منفصل بدل تعديل `main` مباشرةً.

### 5. عدّل وراجع (8 دقائق)

خلّ التغيير محددًا وسهل المراجعة. اقرأ الفرق قبل إرساله:

```bash
git diff
```

إذا كان المشروع يطلب اختبارات أو فحوصات للتوثيق، شغّلها واتبع تعليمات ملف المساهمة. لا تضف معلومات غير متأكد منها؛ اسأل أو اذكر مصدرًا موثوقًا.

### 6. أرسل التغيير (5 دقائق)

```bash
git add README.md
git commit -m "docs: fix a typo in README"
git push -u origin docs/fix-typo
```

افتح صفحة المشروع على GitHub واضغط **Compare & pull request**. اشرح باختصار ماذا غيّرت ولماذا، واربط الـ`issue` إن وُجدت. راجع أن التغيير يستهدف المستودع والفرع الصحيحين، ثم أرسل الـ`pull request` وانتظر مراجعة أصحاب المشروع.

## قبل فتح الـpull request

- هل قرأت تعليمات المساهمة؟
- هل التغيير مرتبط بالمطلوب ومحدود النطاق؟
- هل راجعت التعديلات وتحققت من عدم تضمين معلومات حساسة؟
- هل شرحت التغيير بوضوح واحترام؟

قد يطلب المراجعون تعديلات؛ هذا جزء طبيعي من التعاون، وليس رفضًا لشخصك. ناقش الملاحظات وحدّث فرعك عند الحاجة.

## قاموس سريع

- **Repository (مستودع):** ملفات المشروع وسجل التغييرات.
- **Issue:** نقاش أو وصف لمشكلة أو تحسين مقترح.
- **Fork:** نسخة من مستودع شخص آخر ضمن حسابك.
- **Branch (فرع):** مساحة مستقلة للعمل على تغيير.
- **Commit:** تسجيل مجموعة تغييرات برسالة تصفها.
- **Pull request:** طلب دمج تغييرك في المشروع، مع مساحة للمراجعة والنقاش.

## كيف تساهم في هذا الدليل؟

اقترح تحسينًا عبر [فتح issue](https://github.com/asalomeri/arabic-github-contributing-guide/issues) أو أرسل `pull request`. نرحب بالتصحيحات، والأمثلة العملية، والتحسينات التي تساعد المبتدئين. اجعل كل مساهمة واضحة ومحددة، واذكر مصادر المعلومات عند الحاجة.
