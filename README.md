# دليل المساهمة في GitHub بالعربية

دليل عملي يساعدك على البدء بالمساهمة في المشاريع مفتوحة المصدر، من اختيار مشروع مناسب إلى فتح أول `pull request`.

## قبل أن تبدأ

- أنشئ حسابًا على GitHub وسجّل الدخول. إذا أردت العمل على جهازك، ثبّت [Git](https://docs.github.com/get-started/git-basics/set-up-git) وتأكد بتشغيل `git --version`.
- عند إنشاء أول commit، قد يطلب Git إعداد اسمك وبريدك. اتبع [دليل إعداد الهوية](https://docs.github.com/get-started/git-basics/setting-your-username-in-git)، ويمكنك استخدام عنوان GitHub الخاص لإخفاء بريدك الشخصي.
- لا تضع كلمات المرور أو مفاتيح API أو البيانات الشخصية في الملفات أو أمثلة المساهمة.

يمكنك أيضًا المساهمة بتعديل ملف من المتصفح دون تثبيت Git. اتبع تعليمات المشروع واختر الطريقة المناسبة لك.

## أول مساهمة لك خلال 30 دقيقة

ما تحتاج تكون خبيرًا أو تكتب ميزة كبيرة. تحسين صغير وواضح—مثل تصحيح خطأ في التوثيق—مساهمة مفيدة وتعرّفك على طريقة العمل.

### 1. اختر مشروعًا مناسبًا (5 دقائق)

ابحث عن مشروع تستخدمه أو يهمك، ثم اقرأ ملف `README.md` وتأكد أن المشروع ما زال نشطًا. ابحث في تبويبي **Issues** و**Pull requests** عن تعليمات المساهمة، وعن issues موسومة مثل `good first issue` أو `help wanted`.

### 2. افهم المطلوب قبل البدء (5 دقائق)

اقرأ وصف الـ`issue` والتعليقات، وتحقق أن أحدًا لم يبدأ العمل عليها. إذا كانت التعليمات غير واضحة أو التغيير كبيرًا، اسأل في النقاش قبل أن تبدأ. للمساهمة في هذا الدليل، يمكنك البدء بتصحيح معلومة أو تحسين شرح موجود.

### 3. جهّز نسخة من المشروع (5 دقائق)

- اضغط **Fork** لإنشاء نسخة من المشروع في حسابك.
- استنسخ نسختك إلى جهازك، ثم ادخل إلى مجلد المشروع:

```bash
git clone https://github.com/USERNAME/REPOSITORY.git
cd REPOSITORY
```

استبدل `USERNAME` باسم حسابك و`REPOSITORY` باسم المستودع، حتى تستنسخ نسخة الـFork الخاصة بك لا المشروع الأصلي. إذا كنت تعمل من المتصفح، تقدر تعديل ملفات التوثيق مباشرةً باستخدام محرر GitHub بدل استخدام الطرفية.

### 4. أنشئ فرعًا للتغيير (دقيقتان)

```bash
git switch -c docs/fix-typo
```

استخدم اسمًا قصيرًا يصف التغيير، واعمل على فرع منفصل بدل تعديل `main` مباشرةً.

### 5. عدّل وراجع (8 دقائق)

خلّ التغيير محددًا وسهل المراجعة. اقرأ الفرق قبل إرساله:

```bash
git diff
```

إذا كان المشروع يطلب اختبارات أو فحوصات للتوثيق، شغّلها واتبع تعليمات ملف المساهمة. لا تضف معلومات غير متأكد منها؛ اسأل أو اذكر مصدرًا موثوقًا.

### 6. أرسل التغيير (5 دقائق)

```bash
git add README.md
git commit -m "docs: fix a typo in README"
git push -u origin docs/fix-typo
```

افتح صفحة المشروع على GitHub واضغط **Compare & pull request**. اشرح باختصار ماذا غيّرت ولماذا، واربط الـ`issue` إن وُجدت. راجع أن التغيير يستهدف المستودع والفرع الصحيحين، ثم أرسل الـ`pull request` وانتظر مراجعة أصحاب المشروع.

## مثال مرئي: مسار المساهمة

يوضح هذا الرسم أين تذهب تعديلاتك قبل أن يراجعها أصحاب المشروع:

```text
المشروع الأصلي
      |
    Fork
      v
نسختك على GitHub --> فرع للتعديل --> Commit و Push
                                         |
                                         v
                               Pull request للمشروع الأصلي
                                         |
                                         v
                                  مراجعة ثم دمج محتمل
```

مثلًا، إذا وجدت خطأ في شرح أحد المصطلحات، أنشئ فرعًا لتصحيحه وافتح طلب دمج يوضح التصحيح. فتح الطلب لا يعني دمجه تلقائيًا؛ القرار لأصحاب المشروع.

### مثال على وصف طلب دمج

```text
العنوان: تصحيح شرح مصطلح Branch

التغيير: أوضحت أن الفرع مساحة مستقلة للعمل على تعديل.
السبب: لتسهيل فهم المصطلح على المبتدئين.
```

## تمرينان للمبتدئين

1. **تدرّب على قراءة التغييرات:** في نسخة محلية من هذا الدليل، أنشئ فرعًا، وأضف جملة توضيحية إلى `README.md`، ثم شغّل `git diff`. تحقق أن الفرق يعرض الجملة فقط، وأنه لا يحتوي على بيانات حساسة.
2. **تدرّب على طلب دمج:** ادفع الفرع إلى نسختك على GitHub، ثم افتح صفحة إنشاء طلب الدمج وتأكد أن المستودع الأصلي والفرع المستهدف صحيحان. اكتب عنوانًا ووصفًا على نمط المثال أعلاه. لا ترسل الطلب إلا إذا كان التغيير مفيدًا ويتبع تعليمات المشروع.

يمكنك الاكتفاء بمراجعة صفحة الطلب دون إرساله إذا كان التغيير للتدريب فقط.

## مثال عملي: من مشكلة إلى طلب دمج

تخيّل أنك وجدت رابطًا لا يعمل في توثيق مشروع:

1. افتح **Issues** وابحث عن مشكلة موجودة للرابط. اقرأ تعليمات المشروع وتحقق من عدم وجود شخص يعمل عليها. إن لم تجد مشكلة، اتبع سياسة المشروع بشأن فتح واحدة.
2. إذا احتجت توضيحًا، اكتب تعليقًا مثل: «مرحبًا، لاحظت أن رابط التثبيت لا يعمل. هل يمكنني تحديثه بالرابط الرسمي؟» وانتظر الرد إذا كانت قواعد المشروع تطلب ذلك.
3. أنشئ Fork وفرعًا، ثم استبدل الرابط المعطّل بالرابط الصحيح بعد التحقق منه. لا تغيّر ملفات أخرى لا علاقة لها بالمشكلة.
4. راجع التعديل بـ`git diff`، ثم أنشئ commit وارفع الفرع كما في الخطوات أعلاه.
5. عند فتح طلب الدمج، اختر المشروع الأصلي كوجهة، وفرعك كمصدر، واكتب ما أصلحته وأضف رابط الـissue إن وُجدت. لا تضغط زر الإرسال إلا بعد مراجعة الفرق.

```text
الوجهة: المشروع الأصلي / الفرع المطلوب
المصدر: نسختك          / فرع التعديل
العنوان: إصلاح رابط تعليمات التثبيت
الوصف: استبدلت الرابط المعطّل بالرابط الرسمي الصحيح.
```

اسم الفرع المستهدف يحدده المشروع، وليس بالضرورة `main`. إذا طلب أصحاب المشروع قالبًا أو اختبارات معينة، اتبع تعليماتهم.

## بعد إرسال طلب الدمج

- تابع التعليقات والفحوصات، واشكر المراجع واطلب توضيحًا إذا لم تفهم ملاحظة.
- لإضافة تعديل مطلوب، عدّل الملفات على **الفرع نفسه**، ثم نفّذ `git add` و`git commit` و`git push`. سيظهر التعديل في طلب الدمج المفتوح تلقائيًا.
- إذا فشل فحص، اقرأ رسالته واتبع تعليمات المشروع. لا تفترض أن السبب هو تعديلك دون التحقق، واطلب المساعدة إذا بقي السبب غير واضح.
- قد يُقبل الطلب أو يُطلب تغييره أو يُغلق مع توضيح السبب؛ المراجعة فرصة للتعلّم.

## مشكلات شائعة

| المشكلة | ما الذي تفعله؟ |
| --- | --- |
| يطلب Git تحديد الاسم أو البريد عند إنشاء commit | اضبط هويتك باتباع رابط إعداد الهوية أعلاه، ثم أعد محاولة الـcommit. |
| رُفض `git push` بسبب الصلاحيات | تأكد أنك تعمل على نسخة الـFork الخاصة بك، وتحقق من عنوان `origin` باستخدام `git remote -v` ومن تسجيل الدخول. لا تشارك رموز الوصول مع أحد. |
| رُفض `git push` لأن الفرع البعيد يحتوي تغييرات جديدة | اقرأ رسالة الخطأ وافحص الحالة بـ`git status`، ثم اطلب المساعدة أو راجع تعليمات المشروع قبل دمج التغييرات. لا تستخدم `--force` لمجرد تجاوز الخطأ. |
| ظهر تعارض عند تحديث الفرع | لا تحذف التغييرات عشوائيًا. راجع [دليل تعارضات الدمج](https://docs.github.com/pull-requests/collaborating-with-pull-requests/addressing-merge-conflicts/resolving-a-merge-conflict-using-the-command-line) واطلب المساعدة إن لم تتضح الخطوات. |

## قبل فتح الـpull request

- هل قرأت تعليمات المساهمة؟
- هل التغيير مرتبط بالمطلوب ومحدود النطاق؟
- هل راجعت التعديلات وتحققت من عدم تضمين معلومات حساسة؟
- هل شرحت التغيير بوضوح واحترام؟

قد يطلب المراجعون تعديلات؛ هذا جزء طبيعي من التعاون، وليس رفضًا لشخصك. ناقش الملاحظات وحدّث فرعك عند الحاجة.

## قاموس سريع

- **Repository (مستودع):** ملفات المشروع وسجل التغييرات.
- **Issue:** نقاش أو وصف لمشكلة أو تحسين مقترح.
- **Fork:** نسخة من مستودع شخص آخر ضمن حسابك.
- **Branch (فرع):** مساحة مستقلة للعمل على تغيير.
- **Commit:** تسجيل مجموعة تغييرات برسالة تصفها.
- **Pull request:** طلب دمج تغييرك في المشروع، مع مساحة للمراجعة والنقاش.

## كيف تساهم في هذا الدليل؟

اقترح تحسينًا عبر [فتح issue](https://github.com/asalomeri/arabic-github-contributing-guide/issues) أو أرسل `pull request`. نرحب بالتصحيحات، والأمثلة العملية، والتحسينات التي تساعد المبتدئين. اجعل كل مساهمة واضحة ومحددة، واذكر مصادر المعلومات عند الحاجة.
